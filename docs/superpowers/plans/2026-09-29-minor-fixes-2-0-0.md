# Minor fixes after 2.0.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Session detail shows the real packing list name and tells manual/forced confirms apart from scans; the
app moves to Python 3.14 with pinned dependencies.

**Architecture:** Both display bugs are fixed where the data is *read* (`gui/session_browser/`), so sessions already
on disk display correctly too; no file format changes. The Python move is CI config, `ruff.toml`, requirement pins and
the mechanical fixes ruff asks for once it targets 3.14.

**Tech Stack:** Python 3.14, PySide6 6.11, pytest + pytest-qt, ruff 0.16, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-29-minor-fixes-2-0-0-design.md` — read it first; it has the root causes.

- `shared/` is canonical here. Edit it directly and do **not** touch `../shopify-fulfillment-tool`.
- Repo tooling (CLAUDE.md): `/usr/bin/git`, one plain git command per Bash call, no `;`/`&&`, commit with
  `git commit -F <absolute path to a message file>`. Write test files with Write/Edit.
- Test command: `QT_QPA_PLATFORM=offscreen .venv/bin/pytest -q` (a hook blocks other pytest forms; if a
  single-file run like `QT_QPA_PLATFORM=offscreen .venv/bin/pytest -q tests/test_x.py` is refused, run the full suite
  instead; it takes about 20 s). If `.venv` is missing: `ln -s /home/gloopy/Desktop/Projects/packing-tool/.venv .venv`.

## Review Focus

- A summary written before `packing_list_name` existed (key absent) and a registry name present → shows the registry name, not "Unknown". Pinned in Task 1 (`test_the_overview_falls_back_to_the_registry_name`).
- An item record with no `confirmation_method` key (older sessions) → reads `✓ scan`, not blank or crash. Pinned in Task 2 (the scanned item in the test omits the key).
- A Force record carries `quantity` > 1 (the rest of the line) → the metric adds its quantity, not 1. Pinned in Task 2 (`quantity: 3`).
- Two lists in one session where one finishes → the other must stay live, not flip to completed. Pinned in Task 3.
- An unparseable timestamp after the `parse_timestamp` simplification → `None`, never an exception. Pinned in Task 4.
